# 作业登记 · Homework Log

> 托管老师用的作业登记与家长反馈工具。**一个链接，打开就用，数据只在自己手机上。**

线上地址：<https://homework-log-39980.app.workbuddy.host/>

---

## 一句话说清它解决什么

托管班每天的真实流程是：老师在群里收到一堆作业照片 → 抄到本子上 → 晚上逐个孩子对着本子勾"做了没、错几道" → 再挨个给家长手打一段反馈。

**这个工具把中间三段全接了过来**：拍一张作业照片自动拆成条目，勾两下标完状态，反馈文案自动写好，复制就能发。一个班十几个孩子，从一小时压到十几分钟。

---

## 功能

### 1. 拍照识题

- 直接调手机相机，或从相册选图
- **先裁剪再识别**——照片里通常还有别的东西，框出作业区域，只识别那部分
- OCR 自动把整段作业拆成一条条，可手动增删改
- 中文识别做了断字合并，不会把"抄写生字"拆成单个汉字

### 2. 逐项登记，四种状态

每项作业独立标记：

| 状态  | 含义                     |
| --- | ---------------------- |
| 已完成 | 做完且检查过了                |
| 没写完 | 时间不够／卡住了，明天要陪补         |
| 已上交 | 做完了但已经交给老师，不在手上        |
| 回去做 | 只能回家由家长陪同完成（听写、背诵、签字类） |

### 3. 标签 + 手写备注

点选标签，可多选：全对、正确率高、字迹工整、粗心很多、字迹不工整、需订正。  
再补一句自己的话（"第 3 题不会做"），比标签更具体。

### 4. 按学科分组

语文 / 数学 / 英语 + 自定义学科（可手写任意科目名）。  
列表里同学科的作业自动排在一起，组头显示"语文 · 3 项"，扫一眼就知道哪科还剩多少。

### 5. 同班复制

一个班的作业通常是一样的。登记完一个孩子，一键复制给同班其他同学，只需要改个别差异项。

### 6. 日反馈自动生成

按当天的登记结果生成一段可以直接发家长的文案，**不需要自己组织语言**。

### 7. 周反馈

一周的表现汇总成四段：总体情况 / 做得好的 / 要加把劲的 / 下周计划。

- 默认本周，前后可翻页
- **起止日期可自定义**——调休、提前放假、跨周补课都能对上，不强行按周一到周日切

### 8. 可换主题色

8 个预设色 + 任意取色器。换色后按钮、选中态、页面底色全套联动，浅色自动配深字保证看得清，刷新后保持。

### 9. 数据备份 / 恢复

「名单」页可导出 JSON 备份、也可导入恢复。换手机、发给同事共用名单都靠它。

### 10. 装到桌面当 App 用

PWA。从桌面图标打开没有地址栏、没有浏览器上下栏、固定竖屏，和原生 App 的操作感一致。

## 它跟市面上的托管系统不一样在哪

市面上的托管/教培 SaaS 大多是"卖给机构"的：注册账号、建组织、分配角色、按人头按年收费，功能表能列三页，但真正每天要用的就那几步。

这个工具是**反过来的**——只做老师每天晚上真正要做的三件事，其余全部砍掉。

|             | 纸本 / Excel | 通用托管 SaaS    | 本项目            |
| ----------- | ---------- | ------------ | -------------- |
| 上手成本        | 零，但全靠手写手打  | 要培训、要配置、要录名单 | 打开链接就会用        |
| 花钱          | 0          | 几千到上万／年      | 0              |
| 拍照识题        | ✗          | 多数没有         | ✓ 自带裁剪 + OCR   |
| 反馈文案        | 自己逐条手打     | 通用模板，一眼看出是套话 | 按真实沟通习惯写的规则化文案 |
| 数据在哪        | 本子上        | 服务商服务器       | 只在自己手机里        |
| 断网          | 能用         | 大多不能用        | 能用（离线缓存）       |
| 换颜色 / 跟机构视觉 | ✗          | 要提需求排期       | ✓ 自己点一下就换      |

几个具体的设计取舍，也说明它为什么"顺手"：

**① 反馈只写有事的那几项。**  
完成、没标签、没备注的作业，不逐条罗列占屏，全部并成最后一句「其他作业已全部完成并订正」。家长看到的是重点，不是流水账。

**② 「回去做」不等于「没做完」。**  
听写、背诵、家长签字这类作业，本来就必须回家做，不能写成"没做完带回去补"——那是负面暗示。文案统一写成「回家和您一起完成」，责任在双方而不是孩子一个人。

**③ 「没写完」是独立状态。**  
和「回去做」分开，对应的话术也不同：一个是承诺次日陪补，一个是请家长配合。

**④ 语气是照托管老师跟家长说话的方式定的。**  
不是"本次作业完成率 85%"这种报表语言，而是"今天 6 项作业，有 2 项没写完，明天我陪他补上"。

**⑤ 不做账号，不做云端。**  
学生姓名这类信息不落到任何服务器上，机构不用为数据合规操心，也不用担心服务商涨价、停服、跑路。一个链接发给同事，各自的数据互相看不见。

**⑥ 单文件，零依赖，零构建。**  
整个应用就是一个 `index.html`。拷到 U 盘、放内网服务器、扔任何静态托管都能跑，不怕环境变了打不开。

## 数据怎么存（重要）

全部存在浏览器 `localStorage`，键名 `hwbook.v1`。代码里**没有任何 `fetch` / `XMLHttpRequest` / `sendBeacon`**，学生的任何信息都不会离开这台设备。

因此需要知道：

- **换手机、清缓存、换浏览器 = 数据清零**，请定期用「名单 → 备份数据」导出 JSON
- 备份文件可以直接发给别人，对方「恢复备份」就能拿到同一份名单
- 两个人打开同一个链接，数据完全独立，互不影响

## 关于全屏：为什么不做"网页全屏"

早期版本做过浏览器 Fullscreen API 的"全屏按钮"，结果在安卓上一点就转横、转不回来。原因是浏览器进全屏后会把它当成视频播放场景，自动把画面转横；而唯一能锁定方向的 `screen.orientation.lock()`，在多数国产浏览器和微信内置浏览器里根本没有实现。

所以现在**不调用任何全屏 API**，改成引导"添加到主屏幕"：

- 装到桌面后，方向由 `manifest.webmanifest` 里的 `orientation: "portrait"` 决定，这是系统级窗口，浏览器改不了
- 横屏时也不做任何遮挡，只压薄上下栏，页面始终可操作——宁可不好看，也不把人拦在外面

## 技术

原生 HTML / CSS / JS，零依赖、零构建。

OCR 使用 [tesseract.js](https://github.com/naptha/tesseract.js) 5.1.0，经 unpkg 加载，中文语言包为 1.7MB 量化版（完整版约 20MB，没必要）。

## 本地运行

直接双击 `index.html` 就能用。要测 PWA 和 Service Worker，起个本地静态服务：

```bash
python -m http.server 8000
```

然后访问 `http://localhost:8000`。

## 部署

任意静态托管都可以，把上面几个文件原样上传即可。注意 `sw.js` 里有一个缓存版本号，改动前端后把它 +1，否则老用户会读到旧缓存：

```js
const CACHE = 'hwbook-v9';
```
